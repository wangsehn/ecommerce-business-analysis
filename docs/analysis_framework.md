# 业务分析框架设计（第三阶段）

> 设计原则：我不是沿用作者的顺序，而是问"如果我是这家电商公司的数据分析师，管理层最关心什么"。
> 结论：管理层四个追问 → 经营健康度、用户增长与价值、商品与供给侧、履约与体验。

## A. 经营总览（管理层第一问：公司到底怎么样）

- **核心 KPI**：总 GMV、有效订单量、AOV(客单价)、注册用户数、卖家数、在售商品数、月度 GMV 环比。
- **回答的问题**：
  1. 总 GMV 是多少？（有效订单口径，不含运费）
  2. 有效订单量、客单价、用户/卖家/商品规模各多少？
  3. 月度 GMV / 订单 / AOV 趋势是否平稳？哪些月份异常（同比突增突降）？
  4. 地理上（各州）GMV/用户结构如何？
  5. 品类结构如何——哪些品类撑起大盘？

---

## B. 用户价值分析（管理层第二问：增长与用户价值可持续吗）

- **核心 KPI**：新增用户数、复购率、复购频次结构、复购间隔(平均/中位)、Cohort 留存率、RFM(或简化分层)。
- **口径铁律**：用户级一律用 `customer_unique_id`（解释见 `docs/metric_definition.md`），避免用订单级 `customer_id` 数人头。
- **回答的问题**：
  1. 每月新增多少用户？新增是否放缓？
  2. 复购率多少？购买频次集中在几次？
  3. 复购的用户多久回来（间隔天数）？—— 决定"唤醒"运营节奏。
  4. Cohort：不同首购月份的用户，第 1/2/3 期留存率如何？平台留存是否在改善或恶化？
  5. RFM：能否分层出高价值/高频用户，指导运营资源投放？

---

## C. 商品与卖家分析（管理层第三问：靠什么赚钱、供给健不健康）

- **核心 KPI**：品类 GMV/订单量、品类 GMV 集中度、品类运费占售价比、卖家梯队结构、头部卖家 GMV 依赖、差评卖家风险。
- **避免只做排行榜**：排行榜是描述，这里的价值在"结构判断"。
- **回答的问题**：
  1. 哪些品类 GMV/订单最高？高 GMV 与高订单是否同一批（低价高频 vs 高价低频）？
  2. 品类 GMV 集中度多高（top 品类占多少）？—— 过度依赖单一品类是否风险？
  3. 哪些品类运费敏感（运费占售价比高）？—— 影响定价与包邮策略。
  4. 卖家结构：头部/腰部/长尾各贡献多少 GMV？平台是否过度依赖头部？
  5. 是否存在高 GMV 但低评分的卖家（结构性风险）？

---

## D. 物流与满意度（管理层第四问：履约体验是不是短板）

- **核心 KPI**：平均/中位配送天数、准时率、超时率、超时天数分布、地区/卖家物流表现、配送时长↔评分关联。
- **重点研究**：**物流 → 评分 → 用户体验** 的传导链。
- **回答的问题**：
  1. 平均配送多久？普遍是否准时？
  2. 超时单占多少？超时几天为主？
  3. 哪些地区履约压力最大（超时率高且订单量大）？
  4. 哪些卖家履约最差（延迟率高）？—— 是否构成体验黑洞。
  5. **配送变慢是否真的拉低评分？**（量化：准时 vs 超时订单均分、配送时长分档均分）

## 0. 数据质量层（所有结论的地基）

先用 `01_data_quality.sql` 核验：各表行数、主键唯一、订单状态分布、缺失率、孤儿引用、支付 1:多、同单多评等，并确认 GMV/客单价等口径在报告中可追溯。

---

## 四主题之间的逻辑闭环

```
经营总览发现问题（GMV/结构/集中度）
   └─→ 用户价值定位增长/复购机会
   └─→ 商品与供给侧判断靠什么赚钱、风险在哪
   └─→ 物流与体验解释"为什么某些增长伴随流失"
所有结论必须能回答"现象 → 分析 → 可能原因 → 业务建议 → 局限"
```
