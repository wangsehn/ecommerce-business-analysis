# 指标定义中心（metric_definition.md）

> 本作品集所有指标口径统一在这里定义，供 README、面试指南、分析报告交叉引用。
> 亮点：每个指标都写清 定义 / 为什么这么定 / 常见坑 / 与某口径的差异。

---

## 订单与金额口径

### 有效订单（Valid Order）
- **定义**：`order_status = 'delivered'` 的订单。
- **为什么**：`canceled`(625)、`unavailable`(609)、`shipped`/`invoiced`/`processing`/`created`/`approved`(约 2000+) 均未完成交付，不能算"成交"。把未交付算进收入是数据分析最常见的虚增错误。
- **数据规模**：有效订单 96,478 单；全部订单 99,441 单；非交付约 2,963 单。

### GMV（商品交易总额）
- **定义**：**有效订单**的商品售价合计 `SUM(order_items.price)`，**不含运费**。
- **为什么不含运费**：平台对商家的 GMV 通常按商品成交价核算；运费多是商家/买家承担的成本，不是商品销售收入。本作品集把"运费总额"单独列示，便于解释。
- **常见坑**：
  - 从 `order_payments.payment_value` SUM → 会重复统计（分期/多笔支付，实测 ~2,961 单多次支付）。
  - 不筛 `order_status` → 虚增。实测全部订单 GMV 13,591,643.70 vs 有效 GMV 13,221,498.11，虚增约 2.8%。
- **本数据集值**：有效订单 GMV ≈ **13,221,498（雷亚尔 BRL）**。

### AOV / 客单价（Average Order Value）
- **定义**：`GMV / 有效订单数(COUNT DISTINCT order_id)` = **137.04**。
- **为什么用 DISTINCT order_id**：一张多商品订单 JOIN 后会产生多行，直接 `COUNT(*)` 会把它算成多单。AOV 分母必须是"订单数"，不是"明细行数"。

### 运费（运费总额）
- **定义**：有效订单 `SUM(order_items.freight_value)` ≈ **2,198,275.64**，运费占售价比约 16.6%（GMV 不含运费）。后面品类分析里会用"运费/售价比"判断哪些品类对运费敏感。

## 用户口径

### 用户（User）= `customer_unique_id`
- **定义**：真实用户用 `customer_unique_id` 去重。
- **为什么不能用 `customer_id`**：`customer_id` 是"订单维度"标识——一个用户反复下单时，每次订单可能映射到不同 `customer_id`（实际是每单一个 customer_id）。用 `customer_id` 数人数会把"多次消费的用户"数成"多个人"。实测 `customer_id` 去重 99,441，与订单数相同；`customer_unique_id` 去重 96,096，才是真实用户数。

### 购买用户（有购买行为用户，Purchaser）
- **定义**：至少有一笔有效订单的 `customer_unique_id` = **93,358**（少于注册用户 96,096，说明部分注册用户从未成交）。

### 复购用户（Repeat Buyer）
- **定义**：有 ≥2 笔**不同有效订单**的 `customer_unique_id`。**只有 2,801 人**。

### 复购率（Repeat Purchase Rate）
- **定义**：`复购用户数 / 购买用户数 × 100%` = **3.00%**。
- **性质**：这是"至少 2 单/至少 1 单"的定义。也可用"复购订单占所有订单"，但本作品集采用前一种，语义更贴近"回头客比例"。
- **业务含义**：3% 复购率极低，说明平台高度依赖新客、复购是最大机会，也佐证"一次性购买市场"特征（巴西 Olist 属促销型消费）。

### 购买频次结构
- 只买 1 单：90,557 人；买 2 单：2,573 人；买 3 单：181 人；买 4+ 单：约 47 人。→ 长尾低频为主。

### 复购间隔（Repurchase Interval）
- **定义**：同一用户相邻两次有效购买的时间差（用窗口 `LAG` 计算，只统计相邻、不算首末跨度）。
- **值**：平均 **79.1 天**，中位数 **29 天**。
- **业务含义**：中位 29 天说明多数复购者约每月回来一次；平均被少数超长间隔拉高。唤醒运营可按"30 天"节奏。

### 新增用户（每月首购用户）
- **定义**：首次有效购买落在该月的 `customer_unique_id` 数。

### Cohort 留存率（Retention Rate）
- **定义**：`同一首购月份用户在第 N 个后置月仍有有效购买的人数 / 该首购月份总用户数 × 100%`。
- **即**：`留存用户 / cohort_size × 100%`。
- **注意**：数据窗口只到 2018-08，靠尾部月份没有足够后置期，解读时只看早期 cohort 才有意义（避免把"数据截断"误读成"留存崩塌"）。

### RFM 分层
- R：距最近一次购买天数（最近=价值高）；F：有效购买单数；M：累计 GMV。用跨用户 30/70 分位标记 高/低，组合成经典 RFM 档位。

## 履约与物流指标

### 配送时长（Delivery Days）
- **定义**：`DATEDIFF(order_delivered_customer_date, order_purchase_timestamp)`（下单→送达）。
- **只对** `order_status='delivered'` 且有送达日期的订单统计。
- **值**：平均 **12.5 天**，中位 **10 天**（已配送 96,470 单）。

### 准时 / 超时（On-time / Late）
- **定义**：实际送达日 `<=` 预计送达日(`order_estimated_delivery_date`) = 准时；`>` = 超时。
- **值**：准时率 91.89%，超时率 **8.11%**（96,470 个有完整配送日期的订单中 7,826 单超时）。

### 超时天数分布
- 准时 93.23%；超时 1-3 天 1.94%；4-7 天 1.87%；>7 天 2.97%。→ 极端超时(>7天)占比不小，是体验重灾区。

### 地区/卖家物流表现
- 按州、按卖家算超时率与平均配送天数。

### 履约↔评分关联（核心洞察）
- **准时单平均评分 4.30 vs 超时单 2.57**，相差 **1.73 分**。
- 配送时长分档：`<=3天 4.46`、`4-7天 4.40`、`8-10天 4.33`、`11-15天 4.26`、`>15天 3.60` → 配送越慢评分越低，且 >15 天后断崖式下降。

## 商品与卖家指标

- **品类 GMV / 订单量**：按有效订单聚合；用 `COUNT(DISTINCT order_id)` 算订单，`SUM(price)` 算 GMV，`COUNT(product_id)` 算件数。
- **GMV 集中度**：`品类累计 GMV / 总 GMV`（`SUM OVER` 实现）。
- **运费占售价比**：`AVG(运费)/AVG(售价)×100%`，衡量该品类对运费敏感度。
- **卖家梯队**：按卖家 GMV 从高到低排名，前 2% = 头部、2%~20% = 腰部、其余 = 长尾（基于分布而非拍脑袋阈值）。
- **卖家集中度**：共享各梯队 GMV 占比，衡量"平台是否过度依赖头部"。
- **差评/低分卖家**：`AVG(该卖家订单评价均分) <= 2.5` 且订单量≥10 视为"体验风险卖家"。

## 评分与体验指标

- **订单均分**：先对每个 `order_id` 平均其所有 `review_score`，再对订单集平均（**避免同单多评拉水**，547 单有多条评价）。
- **整体**：98,167 个有评价订单 → 平均 **4.09**；差评(≤2) **14,438**，差评率 14.61%。
- **差评率**：`评分 ≤ 2 的订单 / 有评价订单 × 100%`。
- **支付方式**：信用卡 75,527 单（主导）、boleto 19,546、voucher 3,791、debit 1,516；各方式评分差异极小（≈4.0-4.2），支付方式不作为体验分化的主要解释。
